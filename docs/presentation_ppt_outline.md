# 项目介绍 PPT 大纲

下面是一套 15 页 PPT 建议结构。每页都包含建议标题、核心内容、建议配图和讲解提示，可直接用于制作答辩或课程展示 PPT。

## 1. 标题页

标题：B 站弹幕数据采集与可视化分析系统

核心内容：

- 本地运行的弹幕数据分析工作台。
- 支持热门榜单、BV 搜索、视频对比、AI 评价和储存清理。
- 技术栈：Python、HTML/CSS/JavaScript、ECharts、JSON 文件储存、OpenAI-compatible API。

建议配图：项目主页面截图，重点露出热门榜单和图表区域。

讲解提示：一句话说明项目不是单纯爬取弹幕，而是把弹幕变成可分析、可展示、可对比的数据产品。

## 2. 背景与问题

核心内容：

- 弹幕数量大、时间分布密集、文本表达碎片化。
- 原始弹幕列表难以观察互动峰值、关键词和用户行为。
- 热门榜单需要按日期归档和快速切换。
- 本地项目容易出现文件越积越大、页面越用越慢的问题。

建议配图：左侧放原始弹幕文本列表，右侧放可视化图表效果。

讲解提示：强调从“看弹幕”升级到“分析弹幕”。

## 3. 项目目标

核心内容：

- 自动采集热门视频或指定 BV 视频弹幕。
- 清洗、过滤并统计弹幕数据。
- 通过图表展示时间分布、长度分布、词云和用户贡献。
- 支持视频对比和 AI 评价。
- 保证本地运行时速度稳定、空间可控。

建议配图：目标列表加一条从采集到展示的流程箭头。

讲解提示：目标分成数据、交互、性能、安全四类。

## 4. 整体功能地图

核心内容：

- 热门榜单：Top 50、日期归档、按需加载。
- BV 搜索：后台任务、分 P、采集诊断。
- 可视化：时间分布、长度分布、词云、用户贡献。
- 对比：多视频指标和弹幕特征对比。
- AI：省钱模式、深度摘要、全量原文、缓存。
- 账号与管理：权限、屏蔽词、API Provider、储存清理。

建议配图：功能模块矩阵或六宫格。

讲解提示：先让观众知道系统完整边界，再进入架构。

## 5. 系统总体架构

核心内容：

- 前端页面负责交互和图表渲染。
- Python 后端负责 API、采集、统计、账号和 AI。
- JSON 文件负责本地数据储存。
- MySQL 结构作为后续迁移方向。

建议配图：引用 `presentation_architecture.md` 的总体架构 Mermaid 图。

讲解提示：突出本地项目低依赖、可运行、可检查的特点。

## 6. 数据采集流程

核心内容：

- 热门榜单采集：获取热门视频、抓取弹幕、计算统计、写入归档。
- BV 搜索：创建后台任务、采集视频信息和弹幕、返回统计与诊断。
- 多分 P 视频支持指定 cid。
- 历史补抓可使用账号级 B 站 Cookie。

建议配图：采集流程时序图。

讲解提示：说明为什么使用后台任务，避免长请求阻塞页面。

## 7. 热门榜单与日期归档

核心内容：

- 当前热门榜单导出到 `web/data/`。
- 历史榜单写入 `data/archive/YYYY-MM-DD/`。
- 最近 14 天可在页面下拉切换。
- 历史归档保持只读，避免误写旧数据。

建议配图：日期归档目录结构截图。

讲解提示：突出“当前榜单”和“历史归档”的边界。

## 8. 弹幕拆分储存优化

核心内容：

- 旧问题：切换榜单时加载整份弹幕，解析和统计成本高。
- 新结构：榜单快照、弹幕索引、单视频统计、单视频弹幕文件分离。
- 日期切换只读轻量文件。
- 点击视频时再加载对应 `danmakus/<BVID>.json`。

建议配图：旧结构和新结构对比图。

讲解提示：这是解决榜单首次加载和切换卡顿的核心改造。

## 9. 可视化分析设计

核心内容：

- 时间分布展示视频内互动峰值。
- 发送时间分布展示用户活跃时段。
- 长度分布反映短弹幕和长评论比例。
- 词云展示高频关键词。
- 用户贡献榜展示活跃用户。

建议配图：主页面图表截图，标注各图表含义。

讲解提示：讲清楚每个图表回答的问题，而不是只列图表名称。

## 10. 视频对比能力

核心内容：

- 热门榜单、BV 搜索和自定义榜单的视频都可以加入对比。
- 对比指标包括互动量、弹幕数、关键词和时间峰值。
- 对比 AI 评价可以总结两个视频观众反馈差异。

建议配图：对比区域截图。

讲解提示：说明对比功能让项目从单视频分析扩展到多视频观察。

## 11. AI 分析设计

核心内容：

- 前端和后端先生成统计摘要、候选词和代表弹幕。
- 后端调用用户自己的 OpenAI-compatible Provider。
- 支持省钱模式、深度摘要和全量原文。
- 结果缓存避免重复调用。
- 模型失败时回退本地分析。

建议配图：AI 分析流程图。

讲解提示：强调 AI 不是无约束聊天，而是基于证据的结构化评价。

## 12. 账号、权限与安全

核心内容：

- 普通用户、管理员、owner 三类权限。
- Session 使用 HttpOnly、SameSite Cookie。
- POST 接口做 CSRF 校验。
- 密码使用 PBKDF2-SHA256。
- API Key 和 B 站 Cookie 账号级加密保存。
- 自定义模型 Base URL 阻止内网和 localhost。

建议配图：权限矩阵或安全链路图。

讲解提示：说明这些设计让课程项目也具备基本工程安全意识。

## 13. 本地储存释放与清理

核心内容：

- 前端搜索历史最多保留 15 个未固定视频。
- 固定到自定义榜单或对比的视频不会自动释放。
- 服务启动自动清理旧全量弹幕、运行时副本、孤儿分库和过期 AI 缓存。
- 管理员页支持占用查看、dry-run 预览和手动清理。

建议配图：管理员储存清理页面截图。

讲解提示：回应本地运行最容易遇到的空间占用问题。

## 14. 测试与工程质量

核心内容：

- 测试覆盖采集、解析、过滤、分析、归档、任务、账号、权限、AI、储存清理和 MySQL 准备工具。
- HTTP smoke 测试验证页面安全响应头、登录 Cookie、CSRF 和普通用户越权拦截。
- 最近完整测试结果：`140 passed`。

建议配图：终端测试通过截图或测试分类表。

讲解提示：说明项目不只是页面功能堆叠，也验证了关键边界。

## 15. 总结与后续展望

核心内容：

- 已实现本地可运行的弹幕采集、分析、对比和 AI 评价工作台。
- 核心优化是弹幕按日期和视频拆分储存，配合按需加载和储存清理。
- 后续可将账号、Session、榜单、统计、任务和 AI 缓存逐步迁移到 MySQL。
- 可继续扩展情绪分类、关键词聚类、更多视频平台和更完整的后台审计。

建议配图：从当前文件模式到未来 MySQL/任务队列的演进图。

讲解提示：收束到项目价值和可扩展性。

## 现场演示脚本

1. 打开 `start.html`，进入主页面。
2. 展示当前热门榜单，切换一个历史日期。
3. 点击一个热门视频，等待单视频弹幕按需加载，展示图表。
4. 输入一个 BV 号搜索，展示后台任务进度和采集诊断。
5. 将两个视频加入对比，展示对比图表。
6. 点击 AI 评价，展示缓存或分析结果。
7. 进入账号中心，展示个人屏蔽词、API Provider 和管理员储存清理。

## 答辩时可重点回答的问题

- 为什么不把所有弹幕一次性加载到前端。
- 为什么热门榜单归档要按日期拆分。
- 为什么单视频统计要单独保存 `video_stats.json`。
- 为什么 AI 分析先做本地摘要而不是直接提交全部原文。
- 当前文件模式如何迁移到 MySQL。
- 本地运行如何控制空间占用。
