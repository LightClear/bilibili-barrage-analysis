# B站弹幕可视化项目三个易落地创新点实施计划

> 依据：`docs/innovation_proposals.md`  
> 生成日期：2026-06-09  
> 筛选目标：优先选择对现有架构改动小、依赖轻、演示效果明确、能在答辩中形成差异化叙事的创新点。

---

## 一、筛选结论

本次建议优先落地以下三个创新点：

| 优先级 | 创新点 | 推荐理由 | 预估工程量 | 新增依赖 | 演示价值 |
|---|---|---|---|---|---|
| P0 | 弹幕真实回放 + 情绪心电图双轨道 | 直接消费 `time_in_video` 核心字段，补足当前静态图表缺少弹幕本体感的问题 | 中，约 1 周 | 零新增强依赖 | 极高 |
| P0 | 跨视频关键词桑基迁移图 + 主题河流 | 用上 14 天归档数据，能回答“梗从哪里来、传到哪里去” | 小，约 3-4 天 | 零新增依赖 | 高 |
| P1 | 轻量弹幕情感分类器 | 支撑心电图、AI 报告和后续氛围分析，工程量小且可独立验收 | 小，约 3-5 天 | 可零依赖词典兜底 | 中高 |

没有优先选择“三模态视频内容画像”的原因：它的展示价值很强，但 vision provider、封面代理、评论接口和模型降级链会带来更多外部不确定性。若答辩准备周期充足，可作为第二阶段增强项；若当前目标是“便于实现”，上述三个点更稳。

---

## 二、创新点 1：弹幕真实回放 + 情绪心电图双轨道

### 目标

把当前静态聚合图表升级为“沿视频时间轴回放”的弹幕体验：上层用 Canvas 轨道展示弹幕飞行，下层用 ECharts 折线展示情绪起伏。用户拖动时间游标时，可以看到同一时间点的弹幕内容、密度和情绪变化。

### MVP 范围

- 支持单个视频的弹幕回放。
- 默认 12 条弹幕 lane，使用贪心分配避免重叠。
- 只渲染当前时间点前后 30 秒的弹幕，避免大数据量卡顿。
- 情绪心电图先使用本地词典和强度词规则计算，不依赖 LLM。
- 弹幕量过大时对心电图进行分钟级聚合或 LTTB 降采样。

### 建议改动

- `src/analyzer.py`
  - 新增 `build_playback_track(danmakus, lane_count=12)`：按 `time_in_video` 排序，输出 `{time, text, lane, color, duration}`。
  - 新增 `build_sentiment_timeline(danmakus, bucket_seconds=10)`：按时间桶聚合情绪均值、弹幕数和峰值。
- `server.py`
  - 新增 `GET /api/playback/track?bvid=...&date=...`。
  - 复用现有 `/api/video-danmakus` 的数据读取逻辑和权限校验方式。
- `web/js/app-playback.js`
  - 新增 Canvas 回放渲染、时间游标、播放 / 暂停、倍速控制。
- `web/js/app-charts.js`
  - 在现有时间分布区域旁增加情绪心电图，或新增独立“回放”面板。
- `web/index.html`、`web/css/dashboard.css`
  - 增加回放面板容器和基础样式。

### 里程碑

1. 后端能返回单视频回放轨道和情绪时间线 JSON。
2. 前端能静态展示某个时间点附近的弹幕 lane。
3. 加入播放 / 暂停 / 拖动游标后，弹幕和心电图同步变化。
4. 使用 2-3 个弹幕峰值明显的视频做演示缓存。

### 验收标准

- 任选一个已有 BV，回放接口返回数据时间有序，lane 编号稳定。
- 5 万条以内弹幕回放不卡死，拖动游标响应明显。
- LLM 不可用、无 API Key 时，心电图仍能通过本地规则展示。
- 答辩演示时能用一句话讲清：“我们让弹幕回到它本来应该出现的位置。”

### 风险与兜底

| 风险 | 兜底方案 |
|---|---|
| 弹幕数量过大导致 Canvas 卡顿 | 只渲染可见窗口；超过阈值时合并同文弹幕或增加时间桶聚合 |
| 情绪词典精度有限 | 先用于趋势展示，不宣称强情感分类精度；后续用轻量情感分类器增强 |
| 部分弹幕缺少 `time_in_video` | 过滤异常数据，并在接口 meta 中返回被过滤数量 |

## 三、创新点 2：跨视频关键词桑基迁移图 + 主题河流

### 目标

把 14 天归档数据从“存起来”变成“看得见的传播路径”。通过桑基图展示关键词 / 梗在不同视频之间的出现关系，通过主题河流展示关键词随日期的热度变化。

### MVP 范围

- 支持选择最近 7 天或 14 天归档数据。
- 提取 Top 20-30 高频关键词。
- 桑基图节点包含“视频”和“关键词”，边权重为关键词在视频中的出现次数。
- 主题河流按日期展示关键词热度变化。
- 点击关键词节点时展示样本弹幕。

### 建议改动

- `src/cross_video_analyzer.py`
  - 新增 `build_keyword_sankey(date_range, top_k=30)`。
  - 新增 `build_theme_river(date_range, top_k=12)`。
  - 复用 `src/analyzer.py` 中的分词与停用词过滤规则。
- `server.py`
  - 新增 `GET /api/cross-video/keywords?days=14&top_k=30`。
  - 返回 `{sankey, theme_river, samples, meta}`。
- `web/js/app-charts.js`
  - 增加 ECharts `sankey` 和 `themeRiver` 渲染函数。
- `web/index.html`、`web/css/dashboard.css`
  - 新增“跨视频传播”区域。

### 里程碑

1. 后端能读取 `data/archive` 或当前归档目录，完成跨视频关键词统计。
2. 前端能渲染桑基图，边权重正确反映出现频次。
3. 前端能渲染主题河流，展示关键词随日期变化。
4. 点击关键词能看到 5-10 条代表弹幕样本。

### 验收标准

- 数据不足时页面展示“归档数据不足”，不会报错。
- 有 7 天以上归档数据时，至少能生成 5 个关键词节点和 5 个视频节点。
- 图表点击交互能帮助讲清“这个词在哪些视频中扩散”。
- 不引入新的前端图表库，继续使用 ECharts。

### 风险与兜底

| 风险 | 兜底方案 |
|---|---|
| 归档数据日期不足 | 降级为当前榜单的“视频-关键词二部图” |
| 高频词噪声较大 | 复用现有屏蔽词；增加最小词长、数字过滤、停用词过滤 |
| 梗名不规范 | 第一阶段使用裸关键词；后续可接入梗知识库进行 slug 归一 |

## 四、创新点 3：轻量弹幕情感分类器

### 目标

为心电图、AI 分析和后续氛围雷达提供统一的情绪基础能力。第一阶段不追求复杂模型，而是用“词典规则 + 可选轻量模型”的方式做到可解释、可降级、可演示。

### MVP 范围

- 输出三类情绪：`positive`、`neutral`、`negative`。
- 输出强度分：`score` 范围为 `[-1, 1]`。
- 支持反讽词、强度词、否定词的简单规则。
- 默认不增加依赖；可选 SnowNLP 作为后续增强。
- 结果可缓存到单视频分析结果中，避免重复计算。

### 建议改动

- `src/analyzer.py`
  - 新增 `classify_sentiment(text)`。
  - 新增 `classify_danmaku_sentiments(danmakus)`。
  - 在 `build_dashboard_payload` 或新接口中注入情感分布。
- `config/sentiment_words.json`
  - 新增正向词、负向词、强度词、否定词、反讽词配置。
- `src/danmaku_store.py`
  - 如需缓存，可增加 sentiment 字段的读写兼容；不破坏旧数据。
- `web/js/app-charts.js`
  - 增加情绪分布柱状图或雷达图入口。

### 里程碑

1. 完成词典配置和 `classify_sentiment(text)`。
2. 用 30-50 条人工样例做基本回归测试。
3. 接入创新点 1 的 `build_sentiment_timeline`。
4. 在 AI 报告 prompt 或摘要 payload 中提供情绪分布，减少 LLM 凭空判断氛围。

### 验收标准

- 对空文本、纯表情、超短弹幕、重复刷屏文本都有稳定输出。
- 本地无网络、无 API Key 时仍可运行。
- 情绪时间线能正确呈现明显正向 / 负向弹幕密集区。
- 配置文件可维护，后续补词不需要改代码。

### 风险与兜底

| 风险 | 兜底方案 |
|---|---|
| B 站梗语义复杂，词典误判 | 在文档中明确“用于趋势辅助，不等同精确情感识别” |
| 反讽语义难以识别 | 增加反讽词表和“高不确定性”标记 |
| 缓存字段影响旧数据 | 使用可选字段，读取时缺失即现算 |

## 五、三周落地计划

### Week 1：情绪地基与回放接口

- 完成 `config/sentiment_words.json`。
- 在 `src/analyzer.py` 实现 `classify_sentiment`、`build_sentiment_timeline`、`build_playback_track`。
- 在 `server.py` 增加 `/api/playback/track`。
- 准备 30-50 条情绪样例，覆盖正向、负向、中性、反讽、否定词。
- 阶段产物：单视频回放数据接口可用，情绪时间线可生成。

### Week 2：回放前端与跨视频统计

- 新建 `web/js/app-playback.js`，完成 Canvas lane 渲染、播放 / 暂停、拖动游标。
- 在 `web/index.html` 增加回放区域。
- 新建 `src/cross_video_analyzer.py`，完成关键词桑基和主题河流数据构建。
- 在 `server.py` 增加 `/api/cross-video/keywords`。
- 阶段产物：弹幕回放可演示，跨视频接口可返回图表数据。

### Week 3：跨视频图表、打磨与答辩素材

- 在 `web/js/app-charts.js` 接入 ECharts `sankey` 和 `themeRiver`。
- 增加关键词节点点击后的样本弹幕展示。
- 为 2-3 个演示视频预生成回放和情绪结果。
- 做一次性能走查：大弹幕量、无归档数据、无 API Key、异常字段。
- 更新 README 或答辩材料，加入三个创新点的演示顺序和兜底话术。
- 阶段产物：三个创新点均可独立展示，且能串成完整答辩故事线。

## 六、答辩展示顺序

1. **先展示弹幕回放**：拖动时间轴，弹幕沿轨道出现，同时心电图起伏。说明项目用足了 `time_in_video`。
2. **再展示情绪分类器**：切到情绪分布或心电图解释，说明本地词典兜底，不依赖外部 API。
3. **最后展示跨视频传播**：打开桑基图和主题河流，说明 14 天归档数据不再只是存档，而是能分析梗传播。

收束话术：

> 我们选择的三个创新点不是堆功能，而是围绕同一条主线：让弹幕从静态统计，变成可以按时间回放、按情绪理解、按视频传播追踪的文化数据。

---

## 七、后续增强方向

- 若时间充足，可把“三模态视频内容画像”作为第二阶段增强，接入封面、评论和弹幕的一致性诊断。
- 若梗传播图效果不错，可继续落地“B 站梗知识库”，把桑基图节点从裸关键词升级为规范化梗条目。
- 若需要论文实验，可扩展情绪分类器，引入 SnowNLP 或 ONNX tiny 模型，与词典法做对比评估。
