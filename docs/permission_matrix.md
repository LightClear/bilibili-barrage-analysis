# 当前权限表（1.1 文件模式）

本文档按当前代码状态整理，用于继续审查权限设计。当前版本以本地文件为主，账号数据写入 `data/accounts.txt`，模型 API 配置写入 `data/secure/` 的本机加密存储。MySQL 接入后，可按本文档映射为数据库权限表。

## 1. 核心概念

| 概念 | 是否写入账号 | 当前取值 | 说明 |
| --- | --- | --- | --- |
| 账号角色 | 是 | `normal`、`admin`、`owner` | 决定后台管理、榜单更新、用户管理等真实权限。 |
| API 能力 | 否，按账号状态推导 | `api_enabled=true` 且当前账号已保存模型 Provider | 决定主页面是否开放 AI 评价。它不是账号角色。 |
| 演示身份 | 否，写入会话 | `normal`、`api`、`admin`、`owner` | 只影响 DEMO 展示，不改变真实账号权限。 |
| 本地访问令牌 | 是，账号字段 | `bili_demo_...` | 本地 DEMO 鉴权预留令牌，不是模型 API Key。上线或提交前应删除/隐藏。 |
| 模型 API Key | 否，不写入账号文件 | 用户自带 Provider 配置 | 只按当前登录账号保存和读取，前端只显示脱敏值。 |

注意：`api` 当前不是账号权限等级。用户能否使用 AI/API 功能，由当前账号自己的 API 开关和当前账号自己的模型配置共同决定。

## 2. 权限等级关系

```text
未登录 < normal < API 能力用户 < admin < owner
```

| 等级 | 说明 |
| --- | --- |
| 未登录 | 可访问公开页面、注册登录、公开查询等入口。 |
| normal | 登录后的普通账号，可维护个人资料、个人屏蔽词、个人 API 设置。 |
| API 能力用户 | 普通账号开启 API 开关，并保存了本账号自己的模型 Provider。 |
| admin | 管理员，可进入后台、更新当前热门榜单、管理普通账号的非 API 项。 |
| owner | 项目负责人，继承管理员能力，并负责更高风险的数据和权限管理。 |

## 5. 管理员与 owner 边界

| 行为 | admin | owner | 当前规则 |
| --- | --- | --- | --- |
| 管理普通用户资料 | 可 | 可 | admin 和 owner 都能处理普通账号的非 API 项。 |
| 禁用普通用户 | 可 | 可 | 用于演示账号管控。 |
| 修改普通用户搜索间隔 | 可 | 可 | 间隔范围当前为 0 到 3600 秒。 |
| 开关普通用户 API 状态 | 不可 | 不可 | API 开关只能账号本人修改。 |
| 将普通用户提升为 admin | 不可 | 可 | 只有 owner 可以授予管理员权限。 |
| 将普通用户提升为 owner | 不可 | 不可 | owner 账号只能服务器端创建。 |
| 修改 admin 账号 | 不可 | 可 | admin 不能管理同级或更高级账号。 |
| 降级 admin | 不可 | 可 | owner 可以回收管理员权限。 |
| 修改 owner 账号 | 不可 | 可，有限制 | 不能撤销或禁用自己的 owner。 |
| 禁用自己 | 不可 | 不可 | 当前避免把系统最高权限账号锁死。 |

| 场景 | 未登录 | normal / API 能力用户 | admin / owner | 当前说明 |

| 用户搜索间隔配置 | 不适用 | 由管理员或 owner 修改 | 可修改普通用户 | 当前范围 0 到 3600 秒。 |
| AI 分析 | 不允许 | 允许时受 AI 间隔限制 | 允许时受 AI 间隔限制 | 必须具备当前账号 API 能力。 |
| 当前热门榜单刷新 | 不可 | 不可 | 60 秒间隔 | 通过任务接口执行。 |
| 历史归档榜单刷新 | 不可 | 不可 | 已停用 | 历史归档文件不再写回。 |

## 7. CSRF 与密钥保护

| 类型 | 当前策略 |
| --- | --- |
| 登录、注册、邮箱验证码 | CSRF 豁免，因为登录前没有稳定 CSRF Token。 |
| 登录后的 POST 请求 | 要求携带 `X-CSRF-Token`。 |
| 同源检查 | 已加入，用于降低跨站点伪造请求风险。 |
| 本地访问令牌 | 当前会显示给本人；仅作 DEMO 预留，提交或公开前应删除/隐藏。 |
| 模型 API Key | 存入 `data/secure/` 本机加密存储；前端只显示脱敏值。 |
| AI 缓存键 | 包含当前账号和 Provider 指纹，避免账号之间复用模型分析缓存。 |
| 管理员操作 | 需要登录态、管理员权限和 CSRF Token。 |

## 8. 当前待审查点

| 编号 | 当前情况 | 可选调整 |
| --- | --- | --- |
| 1 | 未登录用户也能发起 BV 查询和 BV 查询任务。 | 可保持公开体验；也可要求登录后查询，降低服务器压力。 |
| 2 | 本地访问令牌仍会显示给本人。 | 课程 DEMO 可保留；提交、部署或展示前建议删除、隐藏或只显示一次。 |
| 3 | 文件模式仍是当前主存储。 | MySQL 阶段再接入账号、Provider、日志、榜单归档迁移。 |
| 4 | owner 的数据管理能力尚未完整实现。 | MySQL 阶段补充存储切换、备份、回档、导入导出。 |

## 9. 建议方向

1. 保留 `normal/admin/owner` 三个真实账号角色。
2. 保留“API 能力”为账号状态，不新增真实 `api` 角色。
3. API 调用始终按当前登录 session 的账号读取 Provider，禁止前端传账号决定使用谁的 Key。
4. owner 继承 admin 能力，但 owner 账号只能服务器端创建。
5. 当前热门榜单统一走 `POST /api/jobs/refresh-popular`，历史归档刷新只给 owner。
6. 所有修改型接口继续保留 CSRF Token、同源检查和权限校验。
